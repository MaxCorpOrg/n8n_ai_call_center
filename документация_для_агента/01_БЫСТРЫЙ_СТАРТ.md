# Быстрый старт для нового агента

## 1. Сначала понять текущее положение

Нужно быстро проверить 4 вещи:
- где живет боевой сервер;
- какие компоненты реально работают;
- какой агент активен в ElevenLabs;
- как устроены память и логирование.

## 2. Что считать источником истины

Главный ориентир:
- live-сервер;
- live n8n;
- live ElevenLabs агент.

Локальный репозиторий использовать как рабочую базу документации и файлов, но не предполагать, что он на 100% совпадает с боевым сервером по каждому compose/env/workflow.

## 3. Минимальный порядок действий перед любой работой

1. Прочитать `02_ТЕКУЩЕЕ_LIVE_СОСТОЯНИЕ.md`.
2. Прочитать `07_ПРАВИЛА_БЕЗОПАСНЫХ_ПРАВОК.md`.
3. Проверить последние изменения в `docs/knowledge_base/09_PROJECT_CHANGELOG_AND_STATE.md`.
4. Если задача связана с агентом ElevenLabs, прочитать `04_ELEVENLABS_АГЕНТ.md`.
5. Если задача связана с памятью, прочитать `06_ПАМЯТЬ_POSTGRES.md`.

## 4. Главный принцип работы

Сначала чтение и фиксация факта, потом точечная правка.

Запрещено:
- перестраивать инфраструктуру “на всякий случай”;
- трогать `first_message`, если нет отдельного указания;
- менять телефонию, если задача касается только prompt/логики агента;
- предполагать, что неработающий по docs модуль обязан быть поднят в live.

## 5. Что уже было сделано в этом проекте

- включен memory-контур `postgres_memory + postgrest`;
- `context_fetch` читает из Postgres, а не из fallback;
- стартовая фраза агента синхронизирована с бизнес-требованием;
- live-агент сейчас работает на `gpt-4.1 + eleven_flash_v2_5 + Elena Gromova`;
- защита стартовой фразы от перебивания включена;
- `call_log` и `context_fetch` восстановлены через валидные `tool_ids`;
- добавлен `send_sms_info` для SMS через Mango;
- follow-up переведен на сценарий без `e-mail`, без `telegram username` и без вопроса про мессенджер в SMS-кейсе;
- правило `на этот номер` зафиксировано: использовать номер текущего звонка, а не пересобирать его из речи;
- документация обновлена под актуальное live-состояние.
