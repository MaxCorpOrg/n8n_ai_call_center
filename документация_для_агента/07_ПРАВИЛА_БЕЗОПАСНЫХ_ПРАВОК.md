# Правила безопасных правок

## 1. Базовый принцип

Нельзя править несколько слоев сразу без необходимости.

Сначала понять, где проблема:
- телефония;
- ElevenLabs;
- n8n;
- память;
- Google Sheet.

## 2. Если проблема в голосе и разговоре

Сначала смотреть:
- ElevenLabs prompt;
- LLM;
- TTS;
- turn-taking;
- interruption behavior.

## 3. Если проблема в контексте

Сначала смотреть:
- `context_fetch`;
- `postgres_memory`;
- SQL/таблицы памяти.

## 4. Если проблема в итогах звонка

Сначала смотреть:
- `call_log`;
- Google Sheet;
- формат `call_result` и `next_step`.

## 4.1. Если проблема в SMS

Сначала смотреть:
- `send_sms_info`;
- workflow `ELEVEN_TOOL_SEND_SMS_BRIDGE (draft)`;
- номер текущего звонка `system__called_number`;
- Mango SMS response `result`.

## 5. Что не трогать без необходимости

- `first_message`
- SIP-маршрут
- номер и trunk
- `voice_id`
- `tool_ids`, если сначала не снят live-config и не понятен состав tools
- live webhook URL tools
- правило `на этот номер` -> `system__called_number`
- server-level network/firewall

## 6. Как вносить правки

1. Считать текущее состояние.
2. Сделать минимальное изменение.
3. Перепроверить live-конфиг после правки.
4. Прогнать 1-2 тестовых звонка.
5. Только потом делать следующую правку.

Отдельно после правки в ElevenLabs всегда проверить:
- `LLM`
- `voice_id`
- `tool_ids`
- список active tools
- `disable_first_message_interruptions`

## 7. Чего нельзя делать

- “массовый рефакторинг”, если задача локальная;
- менять и n8n, и ElevenLabs, и память одновременно;
- публиковать новый сервис наружу без необходимости;
- предполагать, что docs важнее фактического live-состояния.
- возвращать старые backup-объекты tools в ElevenLabs без проверки актуальных `tool_ids`
