# Архитектура проекта

## 1. Уровни системы

Проект состоит из нескольких слоев:
- телефония;
- голосовой агент;
- workflow-логика;
- память;
- логирование и аналитика.

## 2. Слой телефонии

Схема:
- Mango принимает/инициирует звонок;
- Asterisk делает SIP bridge;
- ElevenLabs получает голосовой вызов;
- n8n обслуживает webhook и tools.

## 3. Слой агента

В ElevenLabs живет:
- `first_message`;
- system prompt;
- voice-конфигурация;
- LLM-конфигурация;
- turn-taking настройки;
- tool bindings.

## 4. Слой n8n

В n8n находятся:
- `VOICE_INBOUND_AGENT (draft)`;
- `ELEVEN_TOOL_CONTEXT_BRIDGE (draft)`;
- `ELEVEN_TOOL_CALL_LOG_BRIDGE (draft)`;
- webhook-маршруты;
- интеграционная логика с памятью и Google Sheet.

## 5. Слой памяти

Сейчас память реализована через:
- `postgres_memory`;
- `postgrest`;
- чтение через `context_fetch`.

Содержимое memory-слоя:
- `agent_memory`
- `n8n_chat_histories`
- `knowledge_chunks`
- `script_steps`
- `memory_facts`
- `client_source_links`

## 6. Слой логирования

Итог разговора пишется через `call_log` в Google Sheet.

Это отдельный слой от memory Postgres.

## 7. Ключевая идея архитектуры

Телефонию, голосового агента и память нужно рассматривать как связанные, но разные подсистемы.

Нельзя без необходимости менять несколько слоев сразу.
