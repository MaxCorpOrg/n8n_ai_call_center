## Что важно помнить сразу

- Источник истины по боевому состоянию: live-сервер + live n8n + live ElevenLabs.
- Локальный репозиторий уже частично приведен к актуальному состоянию по документации, но не является идеальным зеркалом сервера по всем файлам.
- Для работы с прод-сервером `147.45.213.87` использовать `ssh ai-core-prod-147`.
- На live ElevenLabs сейчас включён `human-answer gate`: агент не стартует продажный блок до живого ответа человека.
- На `2026-04-23` live-autodial дополнительно ужат по anti-waste лимитам:
  - максимум `50` строк `dialing` в день;
  - максимум `10` коротких non-human разговоров в день;
  - максимум `8` `outbound_request_failed` в день.
- Текущий business-opener после человеческого ответа уже не завязан на старое `first_message` как на автозапускаемую реплику.
- На `2026-04-13` в live дополнительно зафиксировано:
  - первая живая реплика после ответа человека должна сразу быть полным business-opener;
  - ранние вопросы про закупки запрещены до явного сигнала, что собеседник не ЛПР;
  - message-service фразы нужно считать автоответчиком, а не живым собеседником.
- У live-агента сейчас рабочая связка: `gpt-4.1 + eleven_flash_v2_5 + Elena Gromova`.
- У live-агента должны быть активны четыре tools: `context_fetch`, `call_log`, `send_sms_info`, `end_call`.
- На сервере уже включены:
  - cron автодеплоя clean-clone;
  - cron backup для `call_center` Postgres;
  - отдельный backup `n8n_data`.
- Для webhook-tools важны валидные `tool_ids`; если они съехали, агент может потерять `context_fetch`, `call_log` или `send_sms_info`.
- В Eleven API есть текущий технический хвост:
  - agent-config живёт в смешанном состоянии `tool_ids + tools`;
  - из-за этого patch built-in tool params через API сейчас не всегда проходит;
  - prompt и live autodial можно обновлять, но tool-schema/voicemail params нужно трогать осторожно.
- Любые инфраструктурные правки нужно делать очень осторожно, с приоритетом сохранения рабочего звонкового контура.
- В repo-root есть дополнительные рабочие материалы, которые нельзя сходу считать мусором:
  - `agent_contact_parser_docs/`
  - `MANGO_отчеты/`
  - `Документация по скриптам `
  - ` Таблицы_контактов `
  - `workflows/Peptide_Expert_YJdwp45LI1dmrsLy_runtime_2026-03-02.json`
- Их назначение описано в `docs/knowledge_base/11_LOCAL_WORKING_MATERIALS.md`.

## Текущий фокус проекта

- AI call center для LipoLong.
- Телефония по схеме `Mango -> Asterisk -> ElevenLabs -> n8n`.
- Память через `postgres_memory` + `context_fetch`.
- Логирование результатов звонка через `call_log` в Google Sheet.
- Follow-up сейчас строится через SMS: без `e-mail`, без `telegram username` и без вопроса про мессенджер в сценарии `на этот номер`.
- Следующий крупный фронт работы: добивать логику звонков агента
  - старт разговора;
  - прохождение автоответчиков и IVR;
  - удержание внимания после первого возражения;
  - value reveal и более сильная презентация продукта.
