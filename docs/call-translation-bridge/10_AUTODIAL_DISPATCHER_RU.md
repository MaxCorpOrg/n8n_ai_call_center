# 10. Автодозвон по таблице `Лиды_обзвон`

Этот документ описывает первый рабочий контур автодозвона для LipoLong.

## Что делает контур

1. Берет контакты из Google Sheet `Лиды_обзвон`.
2. Отделяет исходные контакты от уже записанных логов по `source_system`.
3. Ведет runtime-состояние в PostgreSQL, чтобы:
   - не звонить одному и тому же контакту дважды одновременно;
   - ограничивать число попыток;
   - не превышать дневной лимит живых контактов;
   - останавливать кампанию, когда список реально исчерпан.
4. Запускает outbound-звонок только в окне `10:00–14:00` по МСК.

## Что считать "успехом"

Успехом считается только живой ответ человека и начатый диалог.

Не успех:
- `busy`
- `no_answer`
- сброс до начала разговора
- автоответчик

## Рабочие лимиты

- Рабочее окно: `10:00–14:00` МСК.
- Предпочтительный пик: `10:00–12:00` МСК.
- Максимум успешных живых контактов в день: `15`.
- Максимум попыток на контакт в одном дневном цикле: `3`.

## Логика повторов

- Если контакт не состоялся, он попадает в retry-очередь.
- Если в этот день попытки уже исчерпаны, контакт переносится на следующий день.
- Если list exhausted, кампания получает статус `exhausted` и не стартует заново сама.

## Состояние

Runtime-состояние хранится не в самой таблице контактов, а в PostgreSQL:
- `autodial_campaigns`
- `autodial_queue`
- `autodial_attempts`

Это позволяет:
- синхронизировать seed-лист из Google Sheet;
- сохранять историю попыток;
- отрабатывать timeouts;
- не терять прогресс между запусками n8n.

## Привязка к call_log

Для успешного обновления состояния агент должен передавать в `call_log` стабильный `lead_id`.

Рекомендуемая схема:
- seed-лист использует `source_record_key` как `lead_key`;
- outbound-call получает этот же `lead_key` как `lead_id`;
- `call_log` возвращает тот же `lead_id`, и dispatcher находит нужную очередь.

## Порядок обработки

1. Dispatcher синхронизирует seed-строки из `source_system = xlsx_import`.
2. Dispatcher синхронизирует outcome-строки из `source_system != xlsx_import`.
3. Dispatcher обновляет состояние `dialing`-звонков, которые зависли по timeout.
4. Dispatcher выбирает следующий контакт и ставит outbound-звонок.

## Что важно не ломать

- Не менять логику `call_log` append-only в Google Sheet.
- Не считать seed-строки и outcome-строки одной сущностью.
- Не запускать outbound вне временного окна.
- Не возвращать кампанию в начало после `exhausted`.
