# 03. Подключение любой LLM без поломки телефонии

## Принцип

SIP-контур и LLM-контур должны быть разделены:
- SIP-контур решает, куда идет звонок.
- LLM-контур решает, что говорить в диалоге.

Нода `ГОЛОСОВОЙ АГЕНТ` остается центральной точкой LLM-логики.

## Универсальный контракт LLM

### Вход (минимум)
```json
{
  "session_id": "call-123",
  "lang": "ru",
  "user_text": "Текст клиента",
  "context": {
    "channel": "voice",
    "caller": "+7999..."
  }
}
```

### Выход (минимум)
```json
{
  "assistant_text": "Короткий ответ ассистента",
  "next_step": "ask|answer|handoff|finish"
}
```

## Вариант A: OpenAI-совместимая LLM

Используется нода `@n8n/n8n-nodes-langchain.lmChatOpenAi`.

Что задать:
1. Credentials (API key).
2. Base URL (если не OpenAI).
3. Model ID.
4. Подключение в `ai_languageModel` к `ГОЛОСОВОЙ АГЕНТ`.

Подходит для: Mistral OpenAI API, OpenRouter, локальные совместимые gateway.

## Вариант B: Несовместимая LLM (через HTTP)

Используется нода `HTTP Request` + `Code`:
1. Собрать payload в формат провайдера.
2. Отправить запрос.
3. Нормализовать ответ к `assistant_text`.
4. Передать текст дальше в голосовой канал.

## Вариант C: LLM внутри Eleven Agent

Если логика хранится в Eleven Agent:
- n8n отвечает за маршрутизацию и оркестрацию;
- LLM-поведение меняется в Eleven без изменений SIP-бриджа.

## Требования к prompt (RU)

1. Ответы 1-2 коротких фразы.
2. Без выдуманных фактов и контактов.
3. Если данных мало -> 1 уточняющий вопрос.
4. При риске ошибки -> перевод на оператора/ручной канал.

## Рекомендованные лимиты

- Timeout LLM: `4-8s`.
- Retry: не более `1`.
- Fallback: заготовленная фраза + уточняющий вопрос.

## Чеклист перед переключением LLM

1. SIP-тесты успешны без LLM.
2. `Mango | Route Decision` работает как раньше.
3. `ГОЛОСОВОЙ АГЕНТ` получает новый провайдер модели.
4. Тест 5 реальных диалогов на русском.
5. Замерить latency и процент fallback.
