# Архитектура

## Контур
- `Telegram` — пользовательская панель управления
- `n8n` — оркестратор команд
- `Mistral` — интерпретатор пользовательских запросов
- `cosmetologist_hunter_service.py` — целевой сервис поиска и выгрузки
- `Google Sheets / Drive` — создание новых таблиц
- `local xlsx` — локальная копия для call center

## Поток данных
1. Пользователь пишет в Telegram.
2. `Telegram Trigger` в `n8n` ловит сообщение.
3. `Mistral` переводит сообщение в JSON-действие.
4. `n8n` вызывает локальный HTTP endpoint:
   - `GET /settings/get`
   - `POST /settings/set`
   - `POST /run`
5. Локальный сервис:
   - собирает данные с картографических источников
   - фильтрует релевантность по косметологии
   - нормализует телефоны
   - вычитает уже существующие номера
   - создаёт новую Google-таблицу
   - выгружает локальную `.xlsx` копию
6. `n8n` отправляет пользователю итоговый ответ в Telegram.

## Почему именно так
- логика сбора живёт отдельно от `n8n`, поэтому её проще тестировать и улучшать
- Telegram остаётся удобной панелью управления
- Mistral нужен как слой интерпретации, а не как место хранения бизнес-логики
- формат таблицы полностью совместим с текущим колл-центром
