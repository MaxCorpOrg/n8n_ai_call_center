## Как довести SSH-доступ до нормального состояния

### Выделенный ключ
На машине `max` уже создан отдельный ключ под этот прод:


Или через helper-скрипт из репозитория:

```bash
cd /home/max/n8n_ai_call_center

```

После этого следующий доступ должен идти уже так:

```bash

```

## Автодеплой

### Текущий механизм
По предыдущему отчёту уже создан серверный wrapper:

```bash
/usr/local/bin/n8n-autodeploy-clean
```

Он должен:
- тянуть изменения из clean-clone `n8n_ai_call_center`;
- обновлять stack с `COMPOSE_PROJECT_NAME=n8n-server`;
- при наличии применять `sql/006_observability.sql`.

Локальный исходник логики:

```bash
scripts/n8n-autodeploy-clean.sh
```

### Рекомендуемая cron-задача
Если включаем автодеплой, безопасный базовый вариант:

```cron
*/5 * * * * /usr/local/bin/n8n-autodeploy-clean >> /var/log/n8n-autodeploy-clean.log 2>&1
```

Пояснение:
- каждые `5` минут;
- lock-файл уже есть в скрипте;
- лог пишется в `/var/log/n8n-autodeploy-clean.log`.

### До включения cron обязательно проверить
```bash
sudo /usr/local/bin/n8n-autodeploy-clean
tail -n 100 /var/log/n8n-autodeploy-clean.log
docker ps --format 'table {{.Names}}\t{{.Status}}'
```

Если clean-clone использует живые SQL и `local-files` из рабочего каталога, проверьте:

```bash
grep -n '^SERVER_RUNTIME_ROOT=' /home/aicore/n8n-ai-clean/.env.https
```

Установщик cron из репозитория:

```bash
cd /home/aicore/n8n-ai-clean
sudo ./scripts/install_n8n_autodeploy_cron.sh
```

## Бэкапы и незавершённые риски

### Уже улучшено в коде
- `scripts/backup_n8n.sh`
  - lock-файл
  - `tar tzf` верификация
  - SHA256 checksum
  - cleanup при ошибке
- `scripts/restore_n8n.sh`
  - проверка архива до остановки сервиса
  - pre-restore backup
  - rollback при ошибке

### Критично не закрыто
- по отчёту, `call_center` Postgres отдельно не бэкапится;
- защищён только volume `n8n_data`;
- это значит, что данные звонков и call-center БД пока остаются без нормального backup-runbook.

### Что нужно сделать следующим шагом
1. На сервере включить отдельный backup `call_center` Postgres:
   ```bash
   cd /home/aicore/n8n-ai-clean
   ./scripts/backup_call_center_postgres.sh
   ```
2. Добавить этот backup в cron.
3. Прописать retention и restore-процедуру для него отдельно.
4. Включить cron автодеплоя только после ручного smoke-test `n8n-autodeploy-clean`.
