# 08. Наблюдаемость И QA

## Что логировать
- число найденных `firm_id`
- число успешно разобранных карточек
- число сырых контактов
- число валидных телефонов
- число удалённых дублей
- число реально добавленных строк

## Диагностические артефакты
- `/tmp/*_preview.json` — финальный shortlist
- `/tmp/*_candidates.json` — кандидаты до записи
- сохранённые HTML при сложных кейсах

## Типовые проверки
1. `added_count == requested_count`
2. `all(phone.startswith('+7') for phone in phones)`
3. `len(phones) == len(set(phones))`
4. новые строки начинаются сразу после старых

## Типовые проблемы
- пустая выдача источника
- непарсящийся `initialState`
- нестабильные таймауты
- кодировка названий

## Реакция на проблемы
- уменьшить параллелизм
- увеличить timeout
- добавить fallback query
- повторить сбор только для недостающего объёма
